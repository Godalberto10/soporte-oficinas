# Milestone 4 — Agents

Read CLAUDE.md (sections "Model contract", "Agents", "Priorities",
"Tools" and rules 4 and 5 of "Rules guaranteed by the code").
In this milestone the orchestrator is NOT written (handoff between agents,
global step limit, confirmation, guardrail, citation checking, priority
raising): that is milestone 5. Neither `HFModel` nor the CLI. No dependencies are added.

## Goal
Each agent, given the `State` and a `Model`, does its job over several
turns (think → call allowed tools → observe → answer) and returns its
validated JSON object, recording everything in the trace.

## Expected files
- `src/office_support/agents.py`
- `tests/test_agents.py`

## Order of work
1. Common loop + **knowledge** agent (vertical slice: uses `search_docs`).
   Tests green before moving on.
2. Classifier, diagnosis and escalation agents on the same loop.

## Decisions for this milestone
- **Turn protocol.** In each turn the model returns a single JSON object:
  - tool call: `{"tool": "<name>", "arguments": {...}}`;
  - final answer: the object with the agent's contract keys.
  JSON inside a ```json block is accepted; any other surrounding text
  is ignored. `extract_json(text) -> dict` raises `ValueError` if there is no object.
- **Agent definition** as data: `Agent(name, instructions,
  tools: tuple[str, ...], keys: tuple[str, ...], validate)`.
  `AGENTS: dict[str, Agent]` with the 4 from CLAUDE.md.
- **System prompt generated by code** (`system_prompt(agent, tools)`):
  role, contract keys, turn protocol and, for each allowed tool, its name,
  signature (`inspect.signature`) and `description` from the registry.
  Disallowed tools never appear.
- **Messages:** the first one (`user`) carries incident, office, ticket and
  what is already known from the `State` (type, priority, cause, service…) as
  JSON. Each model response is appended as `assistant` and each observation as `user`.
- **`run_agent(agent, state, model, tools, max_steps=12)
  -> AgentOutput`**, with `AgentOutput(data: dict | None, reason)` and
  `reason` ∈ {`ok`, `unreadable`, `limit`}:
  - each model response and each tool execution adds 1 to
    `state.steps` and appends a `Step` to `state.trace`;
  - a tool not allowed for the agent → error observation, not executed;
  - `ToolError` → error observation, the agent carries on (rule 4);
  - unreadable JSON or JSON that breaks the contract (missing keys, values out
    of range) → observation with the reason; 2 in a row → `reason="unreadable"`;
  - if `state.steps` reaches `max_steps` → `reason="limit"`.
- **Irreversible tools are never executed inside the loop.**
  `knowledge` proposes them in its `action` key
  (`{"tool": "restart_service"|"close_ticket", "arguments": {...}}`);
  if it tries to call them as a turn, an observation is recorded telling it
  to propose them in `action`. Confirming and executing belong to the orchestrator (milestone 5).
- **Escalation:** after its valid final answer, the code calls
  `create_escalation` with `summary` and `priority` (and the ticket from the
  state) and records it in the trace as a step of the `escalation` agent. So there is always an id.
- **Apply to the state:** each agent copies its output into the `State`
  (classifier → `type`, `priority`; diagnosis → `cause`, `service`;
  knowledge → `procedure`, `citations` and, if there is an action, appends it to
  `actions`). Escalation stores its id in the output.

## Contract validation (in code)
- classifier: `type` ∈ types from CLAUDE.md, `priority` ∈ P1–P4, `reason` non-empty text.
- diagnosis: `cause` non-empty text; `service` one of the 7 services or `null`;
  `evidence` list of texts.
- knowledge: `procedure` text or `null`; `citations` list of texts;
  `action` `null` or an object with an irreversible `tool` and a dict `arguments`.
- escalation: `summary` non-empty text; `tried` list of texts; `priority` ∈ P1–P4.

## Acceptance criteria
1. `extract_json` accepts a bare object, one inside ```json and one with
   surrounding text; raises `ValueError` with text without an object or with a list.
2. Each agent's `system_prompt` contains its keys and its allowed tools
   (with description) and no other tool from the registry.
3. **Knowledge, happy path:** with a `ScriptedModel` that first calls
   `search_docs` and then answers, the output is `ok`, the state has
   `procedure` and `citations`, and the trace has 3 steps (model, tool,
   model) with the real observation from `search_docs`.
4. **Knowledge with action:** a `restart_service` `action` ends up in
   `state.actions` and the service is still not restarted in the `Network`.
5. **Irreversible as a turn:** if knowledge calls `restart_service`
   directly, it is not executed (the `Network` does not change) and the trace records it.
6. **Disallowed tool:** classifier calling `check_service`
   → error observation, not executed, the agent carries on and ends `ok`.
7. **ToolError as observation:** diagnosis queries a non-existent office,
   receives the error in the trace and then answers correctly → `ok`.
8. **Unreadable:** 1 unreadable response followed by a valid one → `ok`;
   2 in a row → `unreadable`. An output with missing keys or an invalid `type`
   counts as unreadable.
9. **Limit:** with `max_steps=3` and a model that only calls tools →
   `reason="limit"` and `state.steps == 3`.
10. **Classifier and diagnosis** fill `type`/`priority` and
    `cause`/`service` in the state. The model's priority is stored as is
    (raising it is milestone 5's job).
11. **Escalation** creates the escalation in the `Network` (id `ESC-0001`) with the
    priority from its output, and the id appears in the output and in the trace.
12. The messages sent to the model (`ScriptedModel.calls`) include the
    incident, what previous agents found out and the observations.
13. Code in English, typed, short functions. `uv run pytest` green,
    no network and no `HF_TOKEN`.
